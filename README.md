# سكاي درويد (SkyDroid) 📱

هاتف **أندرويد 12 حقيقي (64-bit)** يعمل داخل GitHub Actions ويُبثّ إلى متصفح هاتفك
بملء الشاشة — بجودة متكيفة مع سرعة الإنترنت لديك.

## كيف يعمل؟

```
GitHub Actions (ubuntu-latest)
├── android : redroid 12.0.0 (الهاتف نفسه، 720×1280)
├── scrcpy  : ws-scrcpy (بثّ الشاشة H.264) + api صغير (أزرار/لقطة/ping)
└── web     : Caddy (بوابة الدخول، حماية بكلمة سر)
        ↓
cloudflared quick tunnel → رابط https://....trycloudflare.com/play/
        ↓
متصفح هاتفك (PWA بملء الشاشة)
```

## المتطلبات

1. حساب GitHub (مجاني).
2. **سر `SKY_PASS`**: من صفحة المستودع ← `Settings` ← `Secrets and variables` ←
   `Actions` ← `New repository secret`:
   - الاسم: `SKY_PASS`
   - القيمة: كلمة سر من اختيارك (هي كلمة سر الدخول للهاتف).
   - إذا لم تضفه، تُستخدم كلمة السر الافتراضية: `skydroid`.

## التشغيل (من الهاتف)

1. افتح المستودع على GitHub ← تبويب **Actions**.
2. اختر **SkyDroid** من القائمة اليسرى ← زر **Run workflow**.
3. (اختياري) ضع رابط APK/XAPK في حقل `apk_url` لتثبيت لعبة تلقائيًا بعد الإقلاع.
4. اضغط **Run workflow** الأخضر وانتظر.
5. راقب السجل (logs): ستظهر أسطر كبيرة فيها الرابط، مثل:
   ```
   SkyDroid يعمل الآن — افتح من هاتفك:
   https://xxxx-xxxx.trycloudflare.com/play/
   ```
   (تجد الرابط أيضًا في ملخص الخطوة أعلى السجل).
6. افتح الرابط من متصفح هاتفك ← أدخل المستخدم `admin` وكلمة السر ← اضغط **تشغيل**.

## التثبيت على الشاشة الرئيسية (PWA)

من متصفح الهاتف (Chrome): القائمة `⋮` ← **إضافة إلى الشاشة الرئيسية** ←
ستظهر أيقونة سكاي درويد. عند فتحها من الأيقونة يعمل التطبيق **بملء الشاشة
الحقيقي ويبدأ البث تلقائيًا بدون ضغطة زر**.

## تثبيت الألعاب والتطبيقات

- **الطريقة السهلة**: أعد تشغيل الـ workflow مع وضع رابط الـ APK/XAPK في حقل
  `apk_url` — يُثبَّت تلقائيًا بعد الإقلاع (يدعم XAPK مع ملفات OBB).
- يدويًا من داخل الهاتف: افتح المتصفح داخل أندرويد وحمّل APK ثم ثبّته.

## قراءة الأداء (ping / fps / bitrate)

أثناء البث تظهر **حبة حالة صغيرة** أعلى الشاشة تعرض مباشرة:
- `86ms` — زمن الاستجابة (RTT) بين هاتفك والسيرفر، يُقاس كل ثانيتين.
- `24fps` — عدد الإطارات المستلمة فعليًا في الثانية الأخيرة.
- `800k` — الـ bitrate الحالي للترميز.

الجودة **تتكيف تلقائيًا**: عند ارتفاع الـ ping أو تقطع الإطارات ينخفض الـ
bitrate (حتى 400Kbps وحجم 480)، وعند استقرار الاتصال يرتفع (حتى 3Mbps وحجم
1080). إذا توقف الفيديو 15 ثانية يُعاد تشغيل جلسة الترميز تلقائيًا.

## الحدود — بصراحة

| البند | الواقع |
|---|---|
| مدة الجلسة | **~5 ساعات و50 دقيقة** كحد أقصى لكل تشغيل (حد GitHub) |
| الحصة الشهرية المجانية | 2000 دقيقة Actions ≈ **~5 جلسات كاملة** بالشهر |
| البيانات | **تُمسح بالكامل** عند انتهاء الـ job — كل جلسة هاتف جديد تمامًا |
| الـ binder | قد يفشل على بعض صور الـ runner — الـ workflow يُظهر خطأ واضحًا بالعربية |
| كرت الشاشة | **لا يوجد GPU** — الألعاب الخفيفة والثنائية الأبعاد تعمل، أما ألعاب 3D الثقيلة فلن تعمل بسلاسة (ترميز برمجي) |

## استكشاف الأخطاء

- **خطأ binder**: أعد تشغيل الـ workflow (قد تحصل على runner بصورة مختلفة).
- **انتهت مهلة الإقلاع**: أعد التشغيل؛ أحيانًا يحتاج redroid وقتًا أطول في أول مرة.
- **شاشة سوداء بعد التشغيل**: انتظر ~30 ثانية ثم اضغط زر ⟳ (إعادة الاتصال) في شريط الأدوات.
- **تقطيع**: طبيعي على إنترنت ضعيف — الجودة التكيفية ستخفض الـ bitrate تلقائيًا.

## البنية التقنية (للمطورين)

- `docker-compose.yml`: الخدمات الثلاث (android / scrcpy / web) مع healthchecks.
- `scrcpy/`: بناء ws-scrcpy من commit مثبّت مع باتشات SkyDroid:
  `patch-ws-scrcpy.py` (إعدادات فيديو 800Kbps/30fps، TCP_NODELAY، نبض
  WebSocket كل 10s، مراسل إحصائيات، مستمع الجودة التكيفية).
- `scrcpy/entrypoint.sh`: اتصال adb، ضبط سرعة أندرويد، مشرف جلسة scrcpy-server.
- `scrcpy/api.js`: مفاتيح (4/3/187)، لقطة شاشة، ping، إعادة تشغيل البث.
- `play/`: واجهة PWA عربية RTL بملء الشاشة.
- `.github/workflows/skydroid.yml`: التشغيل الكامل من تبويب Actions.
